# 本地课程学分与免修

在本机运行的命令行课程学分与免修登记工具。所有数据保存在用户指定的一个
JSON 记录文件中，正常退出后再次打开，课程状态、修读结果与免修历史仍然可查。

## 构建与测试

```bash
go test ./...
go build ./cmd/credit
```

## 使用

每条命令都通过 `-f` 指定记录文件：

```bash
credit -f 记录文件 <子命令> [参数...]
```

文件不存在时从空记录开始；已有文件无法读取或内容损坏时立即报错
（退出码 2），绝不会把它当作空记录覆盖。只有真正发生变更才会写文件，
只读核对与幂等重复不改动文件，写入采用临时文件 + 原子重命名。

同一个 JSON 对象内的字段归属只能确定一次：出现两个完全同名的字段，或
两个字段名只有大小写不同却都会被读取功能识别为同一条记录字段（课程的
`credit` 与 `Credit`、修读的 `student` 与 `Student`、最外层的 `courses`
与 `COURSES` 等），无论两个值是否相同、字段顺序是否相邻，整份文件都判
为内容损坏。规则同时适用于文件最外层和其中的每条课程、学生、要求、修读、
免修记录（例如最外层同时出现 `courses` 与 `COURSES`，第二份即使是空
数组也不会替换第一份；修读里同时有 `student` 和 `Student` 也不能据此
改变所属学生）；字段名按 JSON 解码后的文字并依现有解码规则做大小写折叠
比较，直接写出、Unicode 转义与大小写写法语义等同，不能用转义加大小写的
组合绕开。只出现一次的大小写写法仍然有效（如只有 `Credit` 的课程按该
值读取）；限制只针对同一对象——两门不同课程各有一个 `credit`、不同
学生名下各自的同号要求/修读/免修均属正常记录，编号、名称、依据等字段
值中的大小写按原文保留（学生 s1 与 S1 仍是不同学生），依据或课程名称
的文字内容里提到字段名也不算重复。不指向任何记录字段的未知字段继续按
原规则拒绝。

JSON 字符串的原始内容必须能还原为合法 Unicode 文字：字符串中直接写入
的字节不是合法 UTF-8，或 Unicode 转义中出现未配对的高位/低位代理项
（高位代理项后没有紧跟低位代理项、孤立的低位代理项、两个高位代理项
相连等），整份文件都判为内容损坏（退出码 2）——哪怕问题只在一条已
拒绝免修的依据里、或本次核对不涉及的课程名称里，也不会只跳过该条记录
再给出核对结果，更不会用替换后的文字判断编号是否相同。读取只检不修：
不替用户修补转义、不删字符、不改动申请状态，原文件保持不变。合法文字
不受影响：中文、直接写入的补充平面字符、完整的高低代理项转义对、转义
表达的控制字符，以及用户确实写入的“�”（U+FFFD）都按原样使用。

课程开放状态字段一旦明确出现，其值只能是 `true`（开放）或 `false`
（停开）；把它显式写成 JSON 的 `null`（`"open": null`）属于课程记录
内容损坏，整份文件判为损坏并拒绝读取（退出码 2）。标准库把 `null`
解进普通布尔字段时不报错而是留下零值 `false`，若放行就会把“状态尚未
确定”的课程读成明确停开：课程列表显示停开、新增修读因停开被拒绝，之后
任何一次需要保存的操作还会把未定状态固化写成 `false`。因此只要课程的
编号、名称与学分合法而开放状态显式为空，就读取失败：标准错误点名记录
文件与课程编号并说明课程开放状态为空，标准输出不出现课程列表、学生
核对报告或登记成功提示；问题课程尚未被任何要求引用、或本次只查看另一
名学生，也同样拒绝，不能跳过这门课继续办理；直接调用记录读取功能也
只收到错误，不返回可继续使用的记录集。状态字段沿用已有识别规则：只
出现一次的 `open`、`Open`、`OPEN`，以及解码后等同于这些名字的
Unicode 转义写法都指向同一状态，这些写法对应 `null` 时都要拒绝，字段
在课程对象中的位置不影响结果。课程名称、免修依据中的普通文字“null”
（字符串值）不属于状态空值；最外层表示没有记录的空数组或 `null`
列表继续按原规则读取。检查只读不写：原文件全部字节保持不变，不补填
状态、不删除课程、不另存部分记录，即使用户发出恢复开放或登记其他
对象的命令，也先报告文件错误，不借该操作修补文件。字段完全省略时
沿用既有读取规则，本次不改动；`false` 仍是合法停开状态——停开课程
仍可建立要求，停开前已有的修读仍可提交成绩并参与核对，停开只限制
新增修读。

待保存的文字适用同一条合法 UTF-8 规则。命令行参数在本机上可能携带非法
UTF-8 字节，标准库序列化时会把这些字节静默替换成“�”却照常返回成功——
这会改掉免修依据，还可能把两个本来不同的学生编号写成同一个编号，让原本
可以读取的记录文件变成编号重复的损坏文件。因此凡是要写入文件的文字
（课程、学生、课程要求、修读、免修的编号、名称、学期、依据、原因等）都
必须是合法 UTF-8：只要有一条记录的任何一个字段不合法，即使问题只在一条
已拒绝或已撤销免修的文字里，也拒绝整次保存——不删除那条历史、不忽略有
问题的字段、不只保存其他记录，也不替换、清空或修补待保存记录中的原始
字符串。错误会说明存在无法原样保存的文字，并指出记录类别与具体字段。
拒绝保存后，已有记录文件的内容保持原样，原先能够查询的学生与学分仍可
正常查询；目标文件原本不存在时，不会留下新的记录文件或临时文件。命令行
对此沿用保存失败的退出码 2：标准错误说明保存失败并点名目标文件，标准
输出不出现登记成功、免修已生效、历史已保存或文件已创建等提示；直接调用
保存功能的程序同样收到错误。合法文字继续按既有规则保存与使用：用户确实
输入的“�”本身是合法字符，中文及补充平面字符不会被误拒绝，编号中合法的
控制字符与免修依据中原有的空白按原文保留；命令行里字面输入的“\uD800”
只是反斜线与普通字母数字，不会被当成记录文件里的 Unicode 转义。


### 学生与课程

```bash
credit -f r.json student s1                    # 登记学生（编号唯一）
credit -f r.json course c1 高等数学 4           # 登记课程，正整数学分，初始开放
credit -f r.json course-close c1               # 停开
credit -f r.json course-open c1                # 恢复开放
credit -f r.json list-courses                  # 列出全部课程及状态
```

学生编号按命令行给出的完整文字匹配，前后普通空格、制表符、全角空格
（U+3000）、不换行空格（U+00A0）也是编号内容，绝不修剪：记录中可以
同时存在“s1”与“ s1 ”两名学生，各自保留完整编号。文件里只有“s1”时
登记“ s1 ”会新建后者，不借用前者名下的课程要求、修读、免修或学分；
只有“ s1 ”时登记“s1”同样新建独立记录。再次登记某个完整编号只判断
对应的那名学生：命中则返回原记录、提示已有记录，不新增副本，也不改动
记录文件；即使两名学生名下有编号相同的要求、修读或免修，重复登记也只
确认对应学生存在，不移动或合并这些历史，更不会为了匹配输入重写其他
记录的学生归属。新登记的带空白编号可直接用于 show 与 check。空字符串
与全部由空白字符组成（普通空格、制表符、全角空格、不换行空格混用）的
学生编号仍以退出码 1 拒绝，不创建学生。

课程未被任何课程要求引用时可以修改学分；一旦被要求引用，修改学分将被拒绝，
原记录保留。

课程编号按命令行给出的完整文字匹配，前后普通空格、制表符、全角空格
（U+3000）也是编号内容，绝不修剪：记录中可以同时存在“c1”与“ c1 ”
两门课程，各自保留完整编号、名称与学分。文件里只有“c1”时提交“ c1 ”
会新建后者，不借用前者的资料或停开状态；再次提交某个完整编号只判断对应
课程，内容不同时的学分限制也只跟随实际命中的那一门——只有要求引用了
“ c1 ”时它才不能改学分，“c1”是否被引用与此无关，反过来也一样。
空字符串与全部由空白字符组成的课程编号仍以退出码 1 拒绝。

### 课程要求、修读

```bash
credit -f r.json req s1 r1 c1                  # 学生 s1 的要求 r1 指向课程 c1
credit -f r.json enroll s1 r1 2024春 e1        # 选课，修读编号在学生名下唯一
credit -f r.json enroll s1 r1 2024春 e2        # 同一学期可多次修读，编号不同即可
credit -f r.json pass s1 e1                    # 提交通过
credit -f r.json fail s1 e1                    # 提交未通过
```

- 同一学生不能为同一课程重复建立要求；要求编号在学生名下唯一。
- 学生编号、要求编号与课程编号都按命令行给出的完整文字匹配，前后普通
  空格、制表符、全角空格（U+3000）也是编号内容，绝不修剪：记录中可以
  同时存在“s1”与“ s1 ”两名学生、“c1”与“ c1 ”两门课程，登记要求必须
  命中编号完全一致的学生与课程并保留三个编号原文。完整学生编号或完整
  课程编号不存在时以退出码 1 拒绝，标准错误指出缺失的是哪一个对象；
  即使去掉空白后能找到另一条记录也不借用，更不自动创建学生或课程。
  空字符串编号不能提交，要求编号全部由空白字符组成时同样拒绝。重复
  登记与冲突判断也按完整编号办理：同一学生名下“r1”与“ r1 ”可以是
  两项要求（仍须指向不同课程），同一完整要求编号改指另一课程整次拒绝，
  完整三元组相同才返回原记录。已有带空白编号的合法记录继续按原样读取，
  不会为登记行为改写、合并或重新解释其中的要求与历史。
- 课程是否停开不改变建立要求的规则：停开课程仍可登记要求，新要求本身
  不带来学分，之后只有通过修读或有效免修才能满足。
- 课程停开后不能新增修读，已有修读仍可提交结果、参与核对。
- 重复登记相同修读、重复提交相同结果直接返回原记录；相同编号换要求/学期、
  已提交结果后改成另一结果一律拒绝，原记录保留。
- 选课和未通过不计学分；同一要求多次通过只得一份课程学分，没有有效免修时
  以最先提交的通过记录说明来源。
- 成绩提交顺序编号按首次提交结果的先后递增分配，通过与未通过都占用一次
  编号，编号是整数类型 `int`。当计数已经达到该类型最大值（64 位环境下
  为 9223372036854775807）时，任何仍处于“选课”的修读都不能再首次提交
  成绩：命令以退出码 1 拒绝，标准错误点名学生与修读编号并说明成绩提交
  顺序编号已用尽、无法提交新的成绩；标准输出不出现提交成功或返回已提交
  成绩的提示。修读保持选课、不获得学分，整份记录文件保持原样，已有结果
  与提交顺序不变。距上限恰好还差一时允许最后一次正常的首次提交（通过、
  未通过都占用这次机会，未通过仍不计学分）；到顶后不能重新从小的编号
  开始、不能借用历史中空缺的编号、也不能改排已有成绩。即使该要求已有
  另一份通过修读或已由有效免修满足，也不放行这次新成绩。已经提交过结果
  的修读不需要新编号：到顶后重复提交相同结果仍成功返回原记录、不增学分、
  不改文件，改成另一结果仍按原有冲突规则拒绝。编号用尽本身不使合法文件
  变成内容损坏，查看与核对继续正常工作。

### 免修

```bash
credit -f r.json waiver s1 r1 w1 学科竞赛获奖      # 提交免修申请（依据非空）
credit -f r.json revoke-waiver s1 w1 材料无法核实  # 撤销有效免修
```

- 免修必须明确指向该学生名下的一项要求，不能跨学生取代要求。
- 目标要求不存在、依据为空、该要求已有有效免修时，申请被拒绝（退出码 1），
  但申请内容与具体原因保留在该学生的免修历史中，核对待会列出。
- 相同编号相同内容重复提交返回原申请及其结果；换内容拒绝；已拒绝/已撤销的
  申请不会因重试重新生效。
- 撤销后保留原依据与撤销状态：有通过记录的要求继续满足，否则重新列为
  未满足；重复撤销不改变结果，撤销不存在的免修明确拒绝。

### 核对与查询

```bash
credit -f r.json check s1                     # 按学生核对学分
credit -f r.json show s1                      # 查看要求、修读与免修历史
```

核对结果列出：总学分、各项要求是否满足及对应来源（通过修读编号或有效免修
编号）、未满足要求、被拒绝的免修及原因。查询没有记录的学生返回明确的不
存在结果（退出码 1）。

课程学分只要求是正整数，接受本程序学分整数类型（`int`）范围内的任意值，
不会另设更小的单课学分上限。但一项学生实际获得的总学分若把各项合法学分
相加后超出该整数类型的最大值（64 位环境下为 9223372036854775807），本次
核对明确拒绝：退出码 1，标准错误点名学生编号并说明总学分超出可表示范围，
标准输出不展示核对报告，也不会给出截断、回绕（例如变成负数）或只累加部分
要求得到的总学分。是否超限只看该学生实际获得的学分：恰为上限仍正常显示
完整数值；选课、未通过、未满足要求、已拒绝或已撤销且没有通过修读的免修
都不计入；同一要求多次通过或通过修读与有效免修并存仍只计一份；其他学生
取得多少学分与本次核对无关。各门课程学分本身合法，因此这不是记录文件
损坏（不使用退出码 2）；核对全程只读，原文件一字不改，仍可用 show 查看
该学生的原始记录。

## 退出码

| 退出码 | 含义 |
| --- | --- |
| 0 | 成功（含幂等命中） |
| 1 | 业务规则拒绝（引用不存在、冲突、被拒绝的免修、学生不存在、核对总学分超出可表示范围、成绩提交顺序编号用尽等） |
| 2 | 记录文件无法读取或内容损坏、保存失败 |
